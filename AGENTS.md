# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

- Purpose, commands and layout: `README.md`. Dataset schema and how to add cases: `docs/dataset.md`. How refs are materialized and why the runtime is what it is: `docs/approach.md`.
- The default extension ref is `main` (`DEFAULT_EXT_REF` in `src/ext/ref.ts`); results are cached per commit sha, so a new `main` commit means a fresh run.
- Never modify the extension clone: refs are read with `git archive` into `cache/module/<sha>/` by the one materializer (`src/module/materialize.ts`), and every bench scores them only through the redaction contract (`contract/`, `src/module/insusty.ts`). The clone path comes from the untracked `bench.local.json`, `INSUSTY_EXT_REPO` or `--ext-repo`; never commit an absolute path.
- Inference must stay on onnxruntime-web WASM with default session options (`onnxruntime-node` is aliased in `package.json`). Native ORT and other graph-optimization levels change greedy outputs on the q8 models, so results would not reflect the extension.
- Models run one at a time, each in its own child process (`src/run/worker.ts`); Qwen2.5-0.5B peaks above 3 GB RSS while loading on a 7 GB machine, so never run two workers in parallel.
- `src/run/transformers-loader.ts` mirrors the extension's `src/model-worker.ts` adapters; when a ref changes that worker, update the loader.
- `npm run dashboard` (`src/dashboard/`) must stay read-only: it watches runs in progress through `cache/active-runs/`, `/proc` and the result cache, and rebuilds plans with `src/run/plan.ts`, the same planner `npm run bench` uses. Keep planning logic there, not in the CLI. Its Playground view is the only part that runs a model: one at a time, in a child process killed on unload/switch (`src/playground/`); never let it hold two models.
- Prompt/model iteration happens in `npm run lab` (`src/lab/`, README "Prompt-engineering lab"): named configs in `src/lab/configs.ts` are `ref` + overrides and results are cached by rendered prompt, so add new configs instead of editing ones `experiments/LOG.md` cites. Keep `experiments/LOG.md` and `experiments/REPORT.md` current after each experiment.
- Shipped Local AI redaction improvements are tracked in `docs/shipped-improvements.md`, with the `shipped` lab baseline and one switch per improvement in `src/lab/shipped.ts`. Whenever an improvement ships to the extension, in the same change: set it in `SHIPPED_CONFIG`, add its switch (a new id, never a changed meaning), add a ledger entry (PR URL, merge commit, evidence incl. held-out), and rerun `npm run ablate`. Measure new proposals against `shipped` (`npm run ablate -- --with <config>`); the doc's "Rejected proposals" lists what was tried and failed, so check it first.
- Candidate models (`models/candidates.json`, `"ort": "next"`) only load on onnxruntime-web 1.24.3 (`onnxruntime-web-next` alias, `src/lab/ort-next-hooks.mjs`); the bench and bundled models stay on the extension's pinned 1.22.0-dev build.
- The `test` split is held out: never tune instructions or label descriptions on it. `npm run split` only fills missing splits. In the lab, tune on `experiments/sets/tune96.json`, confirm on `confirm48.json`, and use `heldout-test.json` (`--allow-test`) only for one-shot checks of choices already made on dev.
- This machine has ~7 GB RAM shared with other lanes: model runs go through the memory waits and guards (`src/lab/runtime.ts`, also used by `npm run bench`); keep ~1.5 GB free (when other lanes hold memory, `LAB_MEM_WAIT_S=3600` makes the lab wait instead of skipping the model after 180 s) and never kill processes you did not start (`pkill -f` patterns also match your own shell). Put scratch installs under `cache/tmp/`, not `/tmp` (tmpfs, eats RAM).
- `npm run detbench` (`src/detbench/`, `docs/detbench.md`) scores the extension's rule-based detector (`src/detection/detector.ts`), no model. Ground truth uses the upgraded category names; map new ref category names in `CATEGORY_ALIASES` (`src/module/labels.ts`), never rename dataset categories. Dataset values must stay fictional and checksum-valid (`--validate`), and secret-looking values raw-free (`--defang-dataset`) so secret scanners do not block pushes.
- New experiments (a model, backend, prompt or setting) must be runnable from `npm run bench` and viewable in `npm run dashboard` afterwards (Live, Results, Lab views): write results in the shared formats the dashboard reads (`cache/results/<sha>/` + `runs/<name>/`, or `experiments/runs/<name>.json` for the lab) and plan through `src/run/plan.ts`, so the dashboard can rebuild the plan. No one-off scripts whose results only live in logs.
- Hosted models: the bench runs only connected models (`src/hosted/connected.ts`, `--models glm47-flash-connected`, never part of `all`) through the ref's own connected-model client; the lab's hosted models (`src/hosted/`, README "Hosted models in the lab": one provider-neutral client, `client.ts`, framings in `framing.ts`, adapters for Bedrock Converse and OpenAI-compatible servers, model table `models.ts`) run by name in `npm run lab`. Keys come only from the environment (`AWS_BEARER_TOKEN_BEDROCK`, or a model's `apiKeyEnv`; never print, log or commit them); send only the fictional dataset. `--budget-usd` (default 5) caps all cached hosted spend. Requests are paced per model (this test account allows Nova Micro 20 requests/min); a new framing, prompt wording, endpoint or decoding setting is a new model id, never an edit (results are cached by model id). Ollama is off when not in use: start `ollama serve` only for a run, stop exactly that process after.
- The extension's "Trusted AI redaction" connected-model client is the source of truth: the bench runs the ref's own client (`src/module/insusty.ts`) and supplies only the transport (`src/hosted/connected.ts`: reply cache, cost, budget); measurement concerns stay there, never request building or parsing. The lab's `src/hosted/` client is a bench-side copy for trying framings the extension does not ship.
- Results are cached by content hash in `cache/results/`; rerunning a bench command with nothing new only rescores. Do not edit files imported by `src/run/worker.ts` (or `src/lab/` during `npm run ablate`) while a run is in progress (each model's worker, and each later lab call, is spawned later and would load the edited code).
